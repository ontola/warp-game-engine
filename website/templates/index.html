The game engine built for iterating with AI.

In Warp everything is code and text, so you and a coding agent can change a game and see the result in seconds: in a window, headless in a container, or live while you play. It is made for couch games, with up to four players on one screen.

Build and run What Warp is

Why Warp

Everything is code

Levels, materials, tuning, rules and sounds live in Rust, Luau, TOML and JSON. An agent can read and change all of it, and every change is a diff you can review, revert and test.

Making a game

Change the game while you play

A running game serves MCP. Ask Claude or ChatGPT to make the shotgun spread wider and let you hear the new shot: it reads the match, edits a weapon or a Luau card, renders the sound, reloads a shader and takes a screenshot to check.

Live control over MCP

Every run replays

The simulation advances in fixed ticks, and the same inputs give the same state bit for bit. State digests find the first tick where two runs differ, scripted playtests become tests, and golden images catch a frame that drifts.

Scripted playtests

Made for the couch

Up to four views render into one output, and the GameNight protocol is built in: controllers by seat, profiles, couch places, phone actions, and pause and resume from the host.

Rendering overview

A short loop

Edit, build, look, measure. Every step is kept short, for a person at a desk and for an agent in a container without a screen.

  1. 2 to 5 sto rebuild after a change in game code. Dependencies are built once with full optimisation, the workspace with light optimisation, so a dev build still plays.
  2. 0 sfor Luau rules, sound patches and shaders: save the file and the running game reloads it, with its state kept.
  3. No GPUneeded to see a frame. The same render path runs on a CPU rasteriser, so a container can render screenshots and compare golden images.
  4. 1 tickis how precisely a regression is found: two runs from the same inputs are compared by state digest, down to the first tick that differs.

What Warp leaves out

Warp is not a general-purpose engine with an editor. Some things are left out on purpose, because they slow down a loop that runs through code and text. Others are simply not built yet.

On purpose

  • No visual editor. There is no scene view to drag things around in. Worlds are generated or described in code and data files, which an agent can read and a reviewer can diff.
  • No visual scripting. Game rules are Rust or Luau, not node graphs.
  • No import wizard. Models are glTF files loaded from code; textures are processed and cached automatically.
  • No separate play mode. The tools live in the running game: debug commands, a Luau console, scripted playtests and live control.

Not yet

  • Water, buildings, indoor scenes and general character animation.
  • The performance target: four views at 4K and 120 frames per second is measured, not yet met.
  • A stable API. Warp is young and changes quickly; the games in the repository move with it.

Ask, and the game changes

Start any Warp game with --live and connect an assistant. It sees the same tools a developer has: the match state, the game's data and scripts, sound patches, shaders and the screen. Nothing is restarted, and the world keeps its state across a reload.

you  make the shotgun spread wider and let me hear the new shot
ai   match_state  player 0         # reads the current Weapon fields
     set_weapon   spread, for all  # live, until the round ends
     set_param    shot             # a heavier, longer shot sound
     render_sound shot             # length, peak, spectrum: judged without speakers
     screenshot                    # checks the pellet pattern on the wall
ai   Wider now, and the shot has more weight. Want it as a card, so it stays?

An illustration of a session; the tool names are the real ones from the live control tools.

What the engine gives a game

PartWhat it doesCrate
Deterministic simulationFixed ticks where the same inputs give the same state, bit for bit. State digests, the first tick where two runs differ, traces of any value over time.kern
Split-screen rendererUp to four views in one output. Cluster LOD selected on the GPU, a visibility buffer, HDR shading in lux and EV100, sun and sky, vegetation, effects, DLSS on NVIDIA.render
Headless renderingEvery frame renders into a texture. The same path runs on a desktop GPU and on a CPU rasteriser, so tests run in a container.render
Live controlAn MCP server inside the running game: state, data, scripts, sounds, shaders and screenshots for an assistant.live
GameNightThe GameNight protocol: seats, controllers and phones, profiles, pause and back from the host.gamenight
Luau scriptingSandboxed modules with hot reload, state that survives a reload, and a step budget so a runaway loop stops at the same point everywhere.script
Synthesised soundEngine sound from the running engine, effects playback, and a procedural synth that places voices from mono to 7.1 with distance, air, occlusion and reverb.audio
Online playA host and clients exchanging the game's own messages over iroh, with relays and hole punching.net
PhysicsBox collision and a character mover for gameplay, Rapier rigid bodies for what tumbles and flies.physics

Try it

From a clone of the repository, with stable Rust:

cargo run -p app --example hello
KERN_ADAPTER=software cargo run -p app --example hello -- --shot hello.png
cargo run --release -p growing-guns-app -- play --live

The first is a ball rolling over a field in a window. The second renders the same game to a PNG on the CPU. The third starts Growing Guns with live control on; connect an assistant and ask it to change something. Then read making a game.
