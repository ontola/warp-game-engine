# Baked explosion smoke

`explosion-smoke.rg8` is an original Warp smoke asset generated by
`engine/tools/bake-explosion-smoke.py`. It contains no third-party VDB samples,
textures or simulation caches. The generator and generated asset are provided
under this repository's MIT license.

The animation is an offline, artist-directed fluid approximation: a seeded
corrugated density source, semi-Lagrangian velocity transport, FFT pressure
projection, buoyancy, vorticity confinement and bounded MacCormack density
transport. A short nonzero-divergence force expands the initial blast. This is
not a combustion solver. Motion is baked; the runtime interpolates frames and
does not simulate or collide smoke with the scene.

## Texture contract

- 32 frames, 48 x 48 x 48 voxels each, 2.6 seconds of source motion, including empty endpoints.
  Runtime preserves the first 1.2 seconds, then eases playback to a 4.6-second
  lifetime. The baked fade runs from source time 1.7 to 2.6 seconds; the shader
  scales its low-density trim by this envelope to retain the thinning wisps.
- Two unsigned normalized bytes per voxel: R density, G directional light
  transmittance (self-shadowing). No header or compression.
- Bytes are ordered `[frame][z][y][x][channel]`, with X advancing fastest.
- The GPU texture is 48 x 48 x 1536; Z contains successive animation frames.
  Clamp each sample to its frame's half-texel centers before interpolating
  frames, so trilinear filtering never leaks across frame boundaries.
- Local coordinates: X/Z from -1 to +1, Y from 0 to 2, bottom-center origin.
- Baked light direction toward the source: normalize((-0.5, 1, 0.4)). G is
  exp(-10 times the density integral) with distance in unit texture coordinates.
  It does not account for changing world lights or scene shadows.
- 7,077,888 bytes (6.75 MiB), shared by all explosions and camera views.
- The adjacent JSON records SHA-256, seed, dimensions and density statistics.

## Generated bounds contract

`explosion-smoke-bounds.wgsl` is generated alongside the texture and JSON from
its quantized R bytes. It contains 32 `SMOKE_BOUNDS_MIN` rows followed by 32
`SMOKE_BOUNDS_MAX` rows, with one `vec4<f32>` per animation frame:

- XYZ are lower/upper bounds in normalized texture coordinates. Voxel index
  `i` maps to `i / 47`; the support of every nonzero density voxel is padded
  by one voxel for trilinear filtering, then clamped to [0, 1].
- MIN.w is zero. MAX.w is the frame's peak quantized density, `max(R) / 255`,
  used as a conservative density bound.
- Empty frames have MIN.xyz = (1, 1, 1), MAX.xyz = (0, 0, 0) and MAX.w = 0.
  The renderer unions adjacent frame bounds during animation interpolation.
- The header records the RG8 asset's SHA-256. Keep the texture, JSON and WGSL
  together on every rebake; stale bounds can clip the smoke's outer wisps.

These bounds let the renderer skip empty space when projecting and marching
smoke. The renderer's `baked_smoke_bounds_cover_quantized_density_and_filter_support`
test checks every exported nonzero voxel against the padded bounds, empty-frame
markers and peak density. Do not edit the generated WGSL by hand.

## Rebuild

Install Python 3, NumPy and SciPy in a development environment; add Pillow for
optional CPU diagnostic projections. There are no runtime Python dependencies.

```sh
python -m pip install numpy scipy pillow
python engine/tools/bake-explosion-smoke.py --preview build/smoke-bake-preview
```

The fixed seed and single-worker solver make repeated runs reproducible within
the same numerical-library versions. FFT/library changes can affect the last
quantization bit; regenerate the JSON checksum and WGSL bounds with the asset.
The bake command writes all three files. The optional
contact sheet and GIF are CPU orthographic diagnostics, not game screenshots
or GPU performance evidence.
